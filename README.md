# CustomVPN

Клиент mihomo для macOS: FlClashX 0.4.2 (окно в menubar), собранный локально, со встроенным [zapret для macOS](https://github.com/Flowseal/zapret-mac-discord-youtube).

- **Вкладка Zapret**: запуск и остановка, доступность YouTube и Discord через zapret (напрямую, мимо VPN), стратегии, IPSet, списки. «Проверить все» прогоняет стратегии по YouTube и Discord мимо VPN и отмечает лучшую. «Обновить стратегии» берёт стратегии, fake-пакеты и списки из релизов Flowseal; скрипты и `utunws` остаются свои.
- **Маршрутизация по умолчанию**: YouTube и Discord идут через fallback-группы `Zapret YouTube` / `Zapret Discord` = `[DIRECT, VPN]`. Если zapret пробивает DPI, трафик идёт напрямую, иначе через VPN, например при выключенном zapret или если провайдер блокирует сервис по IP. После запуска или остановки zapret группы перепроверяются сразу. Фоновая проверка выполняется каждые 300 секунд по одному URL сервиса и не проверяет воспроизведение видео или голос Discord. Включается и выключается виджетом «YouTube и Discord» на главной.
- **Главная**: виджеты «Zapret» (статус, переключатель, стратегия) и «YouTube и Discord» (маршрутизация).
- **Вкладка «Прокси»** объединяет прокси, профили и правила; «Правила» показывают активные правила ядра по порядку, с поиском. Приоритет: сайты, маршруты YouTube/Discord, приложения, профиль. В режиме «Только эти приложения через VPN» правила сайтов и маршруты YouTube/Discord сохраняются, остальной трафик идёт напрямую.
- **Правила сайтов** (раздел «Сайты» в «Правилах»): ссылка очищается до домена перед сохранением. Например, `https://shop.example.com/post/123?id=456#comments` превращается в `shop.example.com`. Правило охватывает поддомены и действует во всех приложениях; более конкретный домен важнее общего. Маршруты: VPN, напрямую, Zapret с резервом VPN, блокировка. Для `youtube.com` и `discord.com` учитываются связанные домены видео, API, вложений и маршруты голоса Discord. Индивидуальное правило связанного домена переопределяет набор сервиса. Настройки хранятся в `~/Library/Application Support/CustomVPN/site-rules.json` и сохраняются при обновлении подписки.
- **Прямые исключения сайтов** обходят VPN и обработку Zapret. Сайты, стратегия, IPSet и переключатель Zapret управляются через установленный контроллер без повторного запроса пароля. При первом переходе на контроллер macOS попросит подтвердить обновление службы. Последующие запросы администратора нужны для обновления её файлов и полного теста стратегий. Пользовательские списки не меняются. Кнопка «Применить правила сайтов» повторяет применение сохранённых правил после ошибки. Для произвольных сайтов маршрут Zapret использует общие HTTP/TLS- и QUIC-профили выбранной стратегии. Доменное исключение требует видимого имени хоста в HTTP, TLS или QUIC; скрытые имена хостов и соединения по IP по домену не распознаются.
- **Правила для приложений** (раздел «Приложения» в «Правилах»): приложение идёт через VPN, напрямую или блокируется. Правила стоят ниже сайтов и маршрутов YouTube/Discord, выше правил профиля и действуют во всех профилях. Приложение `.app` ловится по пути вместе со своими helper-процессами (`PROCESS-PATH-WILDCARD,/Applications/X.app/*`), консольная утилита ловится по имени процесса или пути. Имя и путь могут быть шаблоном: `*` означает любые символы, включая `/`, `?` означает один символ (`codex*` → `PROCESS-NAME-WILDCARD`, `~/.local/share/claude/versions/*` → `PROCESS-PATH-WILDCARD`). Команды в терминале являются отдельными процессами, правило для самого терминала их не ловит. VPN использует группу из `MATCH` профиля, а если `MATCH` ведёт в `DIRECT`, то первую `select`-группу. Хранится в `~/Library/Application Support/CustomVPN/app-rules.json`.
- **Подписки в формате xray JSON** (например, шаблон Remnawave для xray) переводятся в конфиг mihomo: vless (reality, vision, xhttp), vmess, trojan, shadowsocks.
- **zapret совместим с VPN**: pf перехватывает только трафик физического интерфейса, поэтому туннель VPN не задевается, а DIRECT-соединения ядра (работает от root) обрабатываются.

Исходники zapret лежат в [`zapret/`](zapret) (`nfq` — движок, `payload` — скрипты службы и стратегии), данные пользователя лежат в `~/Library/Application Support/ZapretMac`, служба — в `/Library/Application Support/ZapretMac` (имена остались от ZapretMac). Отдельное приложение ZapretMac не нужно: службой управляет CustomVPN. Контроллер `zapret-control` работает в существующем LaunchDaemon, принимает только данные от установившего его пользователя и хранит рабочий конфиг в защищённой папке `runtime`. Новый конфиг проверяется через `utunws --dry-run` до остановки движка; если запуск не удался, восстанавливается прежний конфиг. Выключение Zapret останавливает движок и перехват, контроллер остаётся доступен для следующего запуска. Обычное применение настроек не запускает установщик.

## Сборка (Apple Silicon)

Нужны Xcode, Flutter 3.41.7 и Go 1.26: в `PATH` или в `SDK_DIR=<папка с flutter/ и go/>`.

```sh
./build-local.sh
# SDK_DIR=… ./build-local.sh — свои пути к Flutter/Go
# PROXY=http://127.0.0.1:<port> ./build-local.sh — загрузки через запущенный прокси
# → build/macos/Build/Products/Release/CustomVPN.app (ad-hoc подпись, arm64)
```

Приложение называется **CustomVPN** и имеет свой bundle id (`io.github.zelebo.customvpn`), свои настройки и порт `7895`, поэтому может работать одновременно с FlClash/FlClashX. TUN одновременно может держать только один из клиентов.

## Проверка изменений

```sh
flutter test test/routing_test.dart test/site_rule_dialog_test.dart test/zapret_control_test.dart test/processes_test.dart
(cd zapret/control && go test -race ./...)
(cd zapret/nfq && make test)
```

Go-тесты используют временные папки и имитацию запуска движка. Если `zapret/nfq/utunws` собран, дополнительно проверяются все встроенные стратегии в трёх режимах IPSet через настоящий парсер. Эти проверки не устанавливают службу и не меняют сетевые настройки macOS. После установки новой сборки отдельно проверьте изменение нескольких сайтов и стратегий: после подтверждения обновления службы повторных запросов пароля быть не должно.

Для `make test` нужны macOS, Clang, Python 3 и OpenSSL CLI. Проверка компилирует настоящий парсер и обработчик пакетов во временную папку, подменяет utun/BPF каналом в памяти и передаёт TLS через модель TCP-приёмника. OpenSSL проверяет сертификат тестового сервера, целостность запросов и данных в обоих направлениях. Проверяются TLS 1.2/1.3, X25519/P-256, TCP timestamps, Cloud-хосты, профили YouTube/Discord и приоритет прямого исключения.

В `badseq`-профилях стандартное смещение fake-ACK теперь равно `0x40000000`: подтверждение ещё не отправленных данных заставляет TCP-приёмник отбросить fake. Прежнее смещение `-66000` могло пропустить fake в поток при небольшом положительном смещении SEQ. Режим IPSet `any` по-прежнему обрабатывает обычный HTTPS выбранной стратегией; `none` ограничивает обработку списками и правилами сайтов. Проверка реальных Steam Cloud, обхода DPI, PF и VPN выполняется отдельно после согласования установки, см. [issue](issues/steam-cloud-zapret-timeouts.md).
